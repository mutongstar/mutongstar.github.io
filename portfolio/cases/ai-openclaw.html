AI 工作流与可运行原型

时间
2025 年起，2026 年推进 Agent 与运行原型
产品
OpenClaw 工作流、Figma 方案与 Android Compose 原型
我的角色
工作流搭建、体验设计与原型验证

把产品目标、设计系统和交互约束整理成 AI 可用的上下文，再按要验证的问题选择产物：用 Figma 可编辑稿审阅方案结构，用 Android 可运行原型检验交互和边界状态。

定义任务 · 先写清设计约束与验收条件

  • 设计任务明确用户要完成什么、业务限制是什么。
  • 共享设计约束提供业务知识、设计规范、组件和交互状态，并定义需要人工验收的内容。
  • Figma 可编辑稿检查页面结构、组件一致性和视觉表达。
  • Android 可运行原型用系统控件检查任务流程、状态切换和失败恢复。

选择产物 · 用设计稿审结构，用原型试交互

  • Figma 路径用目标、模块和交互约束生成可编辑稿。人工审阅页面结构和场景适配。验证结构与表达
  • Compose 路径用研发提供的控件和业务知识搭建可交互 Demo，检查操作顺序、状态切换和错误处理。验证实际运行

运行验证 · 用 A/B Demo 推动受阻的 UX 方案通过评审

产品希望推进一项新功能，研发支持预研。UX 方案卡在两个判断上：这个功能在真实场景里有没有价值，以及当时的技术表现能否支撑预期体验。

A/B Demo 的制作与调试用时
2 天
开发调试中的 APK 版本
约 40 个
  1. 制作 A/B Demo研发同步开展技术预研。我把业务知识库和 Figma 设计稿作为输入，接入 Android Compose 系统控件，用 Cursor 生成并迭代可上手的前台交互。原型制作
  2. 接入测试 SDK取得准确率数据后，我将研发提供的测试 SDK 接入 Demo APK，让参与者结合技术参数，在同一场景下体验两种方案。体验验证
  3. 通过团队评审小范围试用反馈正面，方案通过团队验证和评审。后续因三方应用场景适配不足、能力仍偏单点，项目暂缓上线。评审结果

阶段结果 · 把人工审阅带进下一轮设计

已用 OpenClaw 和本地模型搭建多项目工作流，通过 Harness 和 Skill 保留项目约束与验收方式。Figma 稿供设计审阅，Android 原型供运行验证。运行路径使用研发提供的控件与测试能力，设计负责体验整合，并根据审阅和试用结果调整方案。
