AI 工作流与可运行原型

时间
2025 年起，2026 年推进 Agent 与运行原型
产品
DesignKMKit、KM Cert、Figma 与 Android Compose 原型
我的角色
框架与标准定义、验证机制搭建、团队推广与原型验证

我定义了本地设计知识库框架 DesignKMKit，把业务事实、设计规则与工程验证串成一条可追溯的工作链。我进一步定义了五级 AI Native 能力模型，用 Skill 和 Harness 把标准做成可执行的 KM Cert 验证机制，并推广给内部设计师使用。

Design Knowledge Base定义本地设计知识库

1.1 知识结构

DesignKMKit 按用途组织六类知识。页面、组件契约、代码入口和验证记录用同一页面标识关联。

  • 项目边界 范围、平台、技术栈与关键决策。
  • 可追溯输入 PRD、Figma、资产与来源记录。
  • 业务事实 页面、状态、流程与任务包。
  • 设计规则 Token、组件契约与适配规则。
  • 工程落地 预览、Android 实现与质量记录。
  • 项目工具 脚手架、构建与自动化。

1.2 验证链路

从证据到效果沿四步推进，复测时可以定位缺口出在哪一步。

  • 保留来源 记录输入、时间与适用边界。
  • 建立事实 将页面、状态和流程整理为可检索的定义。
  • 约束生成 用设计规则指导生成，与工程契约对齐。
  • 复测结果 从知识重新执行任务，记录运行结果。

Validation Criteria定义 AI Native 能力与验证标准

Figma 可编辑稿用于审阅页面结构和组件一致性。 Android Compose 原型用于实测操作流程和边界状态。基于这些任务，我按知识能够支撑的交付物和达标信号定义了五级 AI Native 能力。

L5

代码共生

设计师通过知识介入真实开发代码，并按代码仓原有方式完成验证。

可交付成果
在可访问的真实代码仓或代码子目录中形成对应的工程变化。
所需知识
真实代码仓、代码子目录或明确工程入口，以及知识与代码的对应关系。
达标信号
找到代码接入线索记为 Ready；完成一次从知识变更到真实代码结果的闭环记为 Certified。
L4

原生交互

使用真实 Native COUI 组件实现可运行、可交互的 Android Demo。

可交付成果
由真实 Native COUI 组件实现的 Android Demo。
所需知识
页面与原生组件的对应关系、主题和样式、交互状态、资源使用方式，以及 Android 构建规则。
达标信号
实现使用正确的组件，关键交互、状态和明暗主题正常，工程可以构建、启动和运行。
L3

设计演进

根据新的业务要求调整设计，并同步更新可运行 Demo。

可交付成果
含模块调整、状态扩展、设备适配或新流程的可运行 Demo。
所需知识
组件组成与可变范围、状态和变体、设备适配、页面和流程的影响关系，以及生成方法。
达标信号
新要求完整落地，受影响内容保持一致，未涉及的内容保持稳定，新增结果遵循已有规则。
L2

真机演示

把已确认的设计结果转成可构建、可安装、可操作的 Demo APK。

可交付成果
可安装、可启动、可完整演示关键业务流程的 Demo APK。
所需知识
页面与交互定义、页面跳转关系、运行方式、构建配置、离线资源和验证要求。
达标信号
能从知识重新构建并安装运行，用户可以完成约定的关键操作。
L1

稳定复现

隐藏现有实现后，仅依靠知识重建已确认的页面与状态。

可交付成果
与已确认设计一致的 HTML Demo 或 Figma 设计稿。
所需知识
页面结构、内容、状态、交互规则、组件使用和视觉资产都有明确记录与来源。
达标信号
仅凭知识稳定生成完整结果，主要页面、内容、状态和交互均可正常使用。

KM Cert 分开记录完整覆盖与局部最高能力。L1、L2 取结构检查与效果实测的较低等级，L3 默认轻度探测，L4、L5 需专项验证。我在 OpenClaw 多项目工作流的基础上，用 Harness 固定测试范围和基线、用 Skill 封装验收流程，再推广给内部设计师，让团队能在同一条件下复测。

Case Examples典型案例

3.1 明确受阻原因

产品要推进一项新功能，研发已开始预研。UX 方案卡在两个判断上：场景有没有价值，当时的技术表现能否支撑预期体验。我决定做一个可体验的 A/B Demo，让团队在同一场景里判断两套方案。

A/B Demo 制作与调试
2 天
开发调试中的 APK 版本
约 40 个

3.2 完成运行验证

  1. 制作前台原型将业务知识库和 Figma 稿作为输入，接入研发提供的 Android Compose 系统控件，用 Cursor 生成并迭代可操作的前台交互。原型制作
  2. 接入测试能力获得准确率数据后，我把研发提供的测试 SDK 接入 Demo APK，让参与者结合技术参数体验两案。体验验证
  3. 推进团队评审小范围试用反馈正面，方案通过团队验证和评审。后续因三方应用场景适配不足、能力仍偏单点，项目暂缓上线。评审结果

这是一次支持产品决策的原型验证。案例记录的是团队实际体验和评审结果。
